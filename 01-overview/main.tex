\section{第一学期的实践项目：ClinicAssistant}

\begin{frame}{ClinicAssistant：电脑诊所工具箱}
  \begin{itemize}
    \item 查看电脑的软硬件信息和运行状态。
    \item 启动一些常用工具。
  \end{itemize}
  \medskip
  \centering
  \includegraphics[
    width=0.95\linewidth,
    height=0.56\textheight,
    keepaspectratio
  ]{assets/clinic-assistant-monitor.png}
  \note{那第一学期做什么项目呢？大家以后一定会听说一位叫金旭亮的老师，他非常厉害。他大二上有一门计算机学院的专业限选课，就是java开发，我当时是诊所的部长，做了一个软硬件信息检测和调用维修工具的程序，叫clinic assistant。它算是我第一个认真写的项目，代码比较简单，大家可以可视化看到程序的样子，所以我们第一学期围绕它展开。
  为了说明我们要对这个项目具体做什么，我先介绍一个它实际工作的工作原理。我们就拿获取CPU温度为例子。}
\end{frame}

\begin{frame}{先看读数：每个数值都有一个编号}
  ClinicAssistant 借助 LibreHardwareMonitor（简称 LHM）读取硬件信息。
  \par\medskip
  LHM用索引和数值的表来储存各个硬件信息。
  \par\bigskip
  \begin{center}
    \begingroup
    \renewcommand{\arraystretch}{1.35}
    \begin{tabular}{cc}
      \textbf{索引（编号）} & \textbf{当前数值（示例）} \\
      \hline
      \alert{7} & \alert{50} \\
      8 & 25 \\
      20 & 12 \\
    \end{tabular}
    \endgroup
  \end{center}
  \bigskip
  哪个指标是CPU温度？
  \note{首先，clinic assistant自己没有能力去读cpu温度这种信息，它是借助了一个叫libre hardware monitor的东西读的，简称LHM。LHM是用列表和对应数值这样去存数据的。我们需要的CPU温度就在这里面。但是到底哪个是CPU温度呢？}
\end{frame}

\begin{frame}{再查名称：CPU 温度对应哪个编号}
  LHM 辅助程序还提供一份清单，列出\textbf{指标名称与编号的对应关系}。
  \par\bigskip
  \begin{center}
    \begingroup
    \renewcommand{\arraystretch}{1.35}
    \begin{tabular}{lc}
      \textbf{指标名称} & \textbf{索引（编号）} \\
      \hline
      \alert{CPU 温度} & \alert{7} \\
      CPU 功率 & 8 \\
      已用内存 & 20 \\
    \end{tabular}
    \endgroup
  \end{center}
  \bigskip
  这个表说明CPU温度对应的索引是7。接下来我们使用索引7向LHM查询，即可得到需要的数值。
  \note{所以，首先它先问这个LHM获取它能读到的信息的列表，也就是左边这样。每个指标有它的名字和索引编号。}
\end{frame}

\begin{frame}{根据索引读取对应的数值}
  清单告诉我们指标的名称和索引；要取得\textbf{当前数值}，还需要按索引请求读取。
  \par\bigskip
  \begin{enumerate}
    \item \textbf{查到 CPU 温度对应的索引是 7}\par
      名称清单中，CPU 温度对应的编号是 7。
    \item \textbf{把索引 7 发给 LHM 辅助程序}\par
      ClinicAssistant 请求：“请读取索引 7 对应的当前数值。”
    \item \textbf{收到返回值 50}\par
      请求的是 CPU 温度，因此这次读到的温度是 \alert{50\,°C}。
  \end{enumerate}
  \note{刚刚那些相当于只是这些指标的名字，我们要想获得具体的值，就得把指标对应的索引发给LHM。比如我们要读第一个CPU温度，那就告诉LHM，我们要索引7的值，它就会把值给我们了。}
\end{frame}

\begin{frame}{用编号读取数值，再保存到程序里}
  ClinicAssistant更新读数，再按记住的编号取值。
  \par\bigskip
  \centering
  \begin{tikzpicture}[
    node distance=7mm,
    stage/.style={
      draw=TalkAccent, rounded corners, align=center,
      inner sep=6pt, text width=0.25\textwidth,
      minimum height=18mm
    },
    ar/.style={-{Latex[length=2mm]}, thick, draw=TalkAccent}
  ]
    \node[stage] (request) {请求编号 \textbf{7}\\对应的读数};
    \node[stage, right=of request] (receive) {收到数值\\\textbf{50}};
    \node[stage, right=of receive] (save) {保存到程序里\\CPU 温度：\textbf{50}};
    \draw[ar] (request) -- (receive);
    \draw[ar] (receive) -- (save);
  \end{tikzpicture}
  \par\bigskip
  \begin{itemize}
    \item 程序知道自己问的是 CPU 温度，就把 50 存到对应位置。
    \item 下次读到 51，就把保存的温度更新成 51。
  \end{itemize}
  \note{之后程序可以把这个数值存起来，供图形界面去调用}
\end{frame}

\begin{frame}{同一个流程，可以有不同的实现}
  刚才展示了一种做法。仅仅是\textbf{什么时候查找索引}，就有多种选择。
  \par\bigskip
  \begin{enumerate}
    \item \textbf{每次读取前都查找}\par
      每次获取 CPU 温度，都先从清单中找到编号，再读取数值。
    \item \textbf{第一次用到时查找并保存}\par
      后续直接使用已存的编号；需要判断这个指标是否已经查过。
    \item \textbf{程序启动时集中查找}\par
      先找齐所有需要的编号，后续直接使用；启动时要做更多准备。
  \end{enumerate}
  \bigskip
  \alert{重复查找的开销、准备工作的时机、代码的复杂程度，都需要权衡。}
  \note{说这个例子是想说明一个事情，就是像刚刚这样一个流程，中间的步骤都有很多不同的实现方法。比如（读）}
\end{frame}

\section{第一学期的计划}

\begin{frame}{第一学期：在小任务中练习设计}
  第一学期主要就是围绕这样的流程，练习设计、实现和改进。
  \par\bigskip
  \begin{itemize}
    \item \textbf{重写一个已有功能}\par
      每次选取流程中的一小部分，小组讨论如何设计、如何实现。
    \item \textbf{阅读并理解已有代码}\par
      理解代码如何组织、如何设计、如何实现，
      也可以试着找找原有的 bug 和不足。
    \item \textbf{整个过程都在小组内分工进行}\par
      从阅读代码、讨论设计，到编写、检查和整合，都由组员分工协作。
  \end{itemize}
  \note{所以呢，我们今年就是围绕一些这样的流程，比如给出某一部分功能的详细描述，大家组内去讨论研究怎么写，然后分工写代码。或者就是让大家去阅读一些已有的代码，理解（读）。当然，整个过程都在小组分工内进行，（读）}
\end{frame}

\begin{frame}{第一学期怎么安排}
  \begin{enumerate}
    \item \textbf{前两次分享会：认识基本概念，做简单练习}\par
      安装开发工具，熟悉基本操作。
    \item \textbf{第二次分享会后：分组，开始项目}\par
      每组五人，由一位部长指导；结合空闲时间和组队意愿安排。
    \item \textbf{后两次分享会及之后：边学边做}\par
      把 ClinicAssistant 的功能拆成小任务，逐步重新实现。\par
      每周统一给出任务，组会上回顾进展、讨论问题。
  \end{enumerate}
  \bigskip
  \alert{组会每周不超过 1 小时，独立写代码每周不超过 3 小时。}
  \note{不过也不是我们一开始就要组队的，毕竟最开始你还啥都不会嘛。所以呢，我们最开始两次技术分享会后才开始组队，这两次（读）}
\end{frame}

\section{软件开发与代码}

\begin{frame}{程序的功能，是用代码写出来的}
  无论是读取 CPU 温度，还是更新界面上的文字，背后都有代码。
  \par\bigskip
  \begin{center}
    \textbf{源代码}
    \quad $\longrightarrow$ \quad
    \textbf{编译、解释等处理}
    \quad $\longrightarrow$ \quad
    \textbf{计算机执行}
  \end{center}
  \bigskip
  \begin{itemize}
    \item 代码描述要做什么，以及怎样做。
    \item 经过编译器、解释器等工具处理，计算机才能执行这些要求。
    \item 软件还会用到图片、配置等资源，代码把它们组织起来。
  \end{itemize}
  \bigskip
  \alert{编程语言，就是我们向计算机表达要求的语言。}
\end{frame}

\begin{frame}{编程语言有很多种}
  不同语言有不同的设计特点，也有各自常见的使用场景。
  \par\bigskip
  \begin{itemize}
    \item \textbf{C：}接近底层，常用于系统和嵌入式开发。
    \item \textbf{Java：}支持跨平台，常用于服务端和桌面应用。
    \item \textbf{Python：}语法简洁，常用于自动化和数据分析。
  \end{itemize}
  \bigskip
  这些场景并不是语言的使用边界，同一个问题也可以用不同语言解决。
  \par\bigskip
  \alert{技术部第一学期学习 Java，并用它实践 ClinicAssistant 的开发。}
\end{frame}

\begin{frame}{开发一个程序，需要掌握什么}
  可以把学习软件开发，类比为学习用一门语言写文章。
  \par\bigskip
  \begin{itemize}
    \item \textbf{编程语言：知道代码怎么写}\par
      就像学习词汇和语法，先能写出正确的句子。
    \item \textbf{开发工具：会编辑、运行和调试程序}\par
      就像写作时会使用字典、文字编辑工具。
    \item \textbf{组织代码：会拆分功能、安排结构}\par
      就像学习谋篇布局和修辞，让表达清楚、便于理解。
  \end{itemize}
  \bigskip
  \alert{只会语法，不代表能写好文章；只会语言，也不代表能写好程序。}
\end{frame}

\begin{frame}{Editor 与 IDE：编写代码的工具}
  两者都能编写代码，区别主要在于\textbf{功能的集成范围}。
  \par\bigskip
  \begin{columns}[T,onlytextwidth]
    \begin{column}{0.47\textwidth}
      \textbf{Editor：代码编辑器}
      \par\medskip
      代表：\href{https://code.visualstudio.com/docs}{VS Code}
      \medskip
      \begin{itemize}
        \item 以代码编辑为核心。
        \item 功能侧重集中，通常较轻量。
        \item 可通过扩展支持运行、调试等。
      \end{itemize}
    \end{column}
    \begin{column}{0.47\textwidth}
      \textbf{IDE：集成开发环境}
      \par\medskip
      代表：\href{https://www.jetbrains.com/idea/features/}{IntelliJ IDEA}
      \medskip
      \begin{itemize}
        \item 集成编辑、运行、调试和重构。
        \item 功能更全面，通常也更耗资源。
        \item 面向 Java 项目，提供较完整的开发支持。
      \end{itemize}
    \end{column}
  \end{columns}
  \bigskip
  \alert{\textbf{协会推荐使用 IntelliJ IDEA 开发 Java。}}
\end{frame}

  \bigskip
  \begin{itemize}
    \item \textbf{逐步积累：}把一次次修改串起来，保留代码的演变过程。
    \item \textbf{出现问题：}比较改动，必要时回到之前记录的版本。
    \item \textbf{回看历史：}追溯某段代码何时加入、当时改了什么。
  \end{itemize}
\end{frame}

    \item \textbf{整合成果：}把不同成员完成的修改合并到一起。
    \item \textbf{处理冲突：}修改发生冲突时，共同确认最终的代码。

\begin{frame}{Git：仓库、提交与分支}
  \alert{\textbf{Git 是版本控制工具，}}
  帮助我们记录代码历史、组织开发并整合修改。
  \par\bigskip
  \begin{itemize}
    \item \textbf{仓库（repo）：管理项目的版本历史}\par
      保存项目文件的历史版本，以及提交、分支等信息。
    \item \textbf{提交（commit）：记录一次修改}\par
      保存选定的修改并写下说明，对应图中的一个记录节点。
    \item \textbf{分支（branch）：让不同任务分别推进}\par
      从已有版本出发，沿不同路线继续提交，也可用于个人尝试新功能。\par
      完成后可合并（merge）修改；有冲突时需要人工处理。
  \end{itemize}
\end{frame}

\begin{frame}[fragile]{命令行工具}
  \alert{\textbf{命令行与图形化界面只是两种交互形式，背后都是软件。}}
  \par\medskip
  \begin{itemize}
    \item \textbf{图形化界面：}通过窗口、按钮和菜单操作软件。
    \item \textbf{命令行界面：}通过输入命令操作软件。
  \end{itemize}
  \medskip
  例如，用 Git 记录已暂存的修改，并写下提交说明：
  \begin{lstlisting}
git commit -m "Update README"
  \end{lstlisting}
  \medskip
  常见的命令行环境：\textbf{Windows 下的 PowerShell}、\textbf{Linux 下的 Bash}。
  \par\medskip
  不同操作系统的命令行语法会有所差异。
\end{frame}

\begin{frame}{有了图形化界面，为什么还用命令行}
  \begin{itemize}
    \item \textbf{参数灵活，便于组合}\par
      通过参数指定操作、文件和选项，直接表达具体要求。
      \medskip
    \item \textbf{操作容易记录和复现}\par
      命令包含操作及其选项，可以保存、复制、修改后再次执行。\par
      向别人说明操作步骤时，也可以直接分享命令。
      \medskip
    \item \textbf{交互形式相对统一}\par
      通常采用“命令名 + 选项 + 参数”的形式，\par
      不必为每个工具重新寻找按钮和菜单；具体参数仍需学习。
  \end{itemize}
  \bigskip
  \alert{熟悉之后，命令行能让我们更直接、准确地表达操作意图。}
\end{frame}

\begin{frame}{日常开发的基本流程}
  \begin{enumerate}
    \item \textbf{明确需求：}要实现什么功能，做到什么程度算完成。
    \item \textbf{阅读已有代码：}打开 IDE，了解已有功能，确定修改的位置。
    \item \textbf{编写代码：}按照需求实现，边写边运行、调整。
    \item \textbf{验证结果：}检查新功能符合需求，相关的原有功能仍然正常。
    \item \textbf{提交修改：}检查本次改动，用 Git 提交并写清修改说明。
  \end{enumerate}
  \medskip
  \alert{遇到不熟悉的语法、接口或工具时，查阅文档，确认用法。}
  \par
  \bigskip
  \textbf{小组协作：}明确需求、共同了解相关代码后，先拆分任务，\par
  约定各自负责的部分和衔接方式，再分别动手实现。
\end{frame}

\section{AI 编程与第一学期的学习}

\begin{frame}{有了 AI，为什么还要自己写代码}
  AI 已经这么发达了，还要按刚才的流程，自己动手写代码吗？
  \par\medskip
  AI 能高效完成许多编程任务，实际开发中，我们应当学会使用它。
  \par\bigskip
  \textbf{但第一学期，我们要求自己写代码：}
  \medskip
  \begin{enumerate}
    \item \textbf{读懂代码，不等于能独立写出来}\par
      从零实现，才能逼着自己拆解问题、组织逻辑、调试错误，\par
      逐步建立对代码的认识。
    \item \textbf{理解代码，才能指挥和监督 AI}\par
      知道怎样说明要求，也能检查实现、判断结果、发现问题。
  \end{enumerate}
  \bigskip
  \alert{AI 是工具，不要反过来被 AI 指使了。}
\end{frame}

\begin{frame}{第一学期，可以怎样使用 AI}
  \textbf{基本要求：自己构思方案，自己实现代码。}
  \par\medskip
  \alert{不允许直接把需求交给 AI，让它生成要实现的代码。}
  \par\bigskip
  \textbf{这些环节，可以请 AI 帮忙：}
  \medskip
  \begin{itemize}
    \item \textbf{询问知识：}学习中有不懂的概念、语法，可以让 AI 解释。
    \item \textbf{讨论方案：}先自己构思，再请 AI 提意见，自己判断和取舍。
    \item \textbf{辅助准备：}帮助查文档、了解工具用法、配置开发环境。
  \end{itemize}
  \bigskip
  本阶段的重点是练习\textbf{构思和实现程序}；\par
  AI 可以辅助学习，但不能替代这部分核心训练。
\end{frame}
