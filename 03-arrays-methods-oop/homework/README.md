# Java 数组、方法与面向对象课后练习

第三次技术分享会的 18 道主线填空题和 2 道附加题。统一使用“文具店商品与库存”场景，学习顺序为：

数组保存多个价格 → 循环处理数组 → 方法复用计算 → 类组织商品信息 → 实例方法处理对象数据 → 封装保护库存。

本目录是一个独立的 Gradle Java 项目，可以单独复制、打开和分发，不依赖父目录、第二次作业或网络上的其他项目文件。

## 学习目标

完成练习后，应能：

- 创建数组、通过索引读写元素、使用 `length` 遍历数组；
- 用普通 `for` 循环求和、计数和批量修改；
- 定义并调用静态方法，传递数组参数，让一个方法调用另一个方法；
- 用字段、对象和构造方法组织一件商品的数据；
- 区分静态成员与实例成员，使用 `this` 访问当前对象；
- 把对象作为方法参数，编写实例方法；
- 使用 `private`、getter、setter 和业务方法保护库存规则；
- 综合运用对象数组、循环和实例方法完成小任务。

本次只使用变量、基本类型、条件、循环、数组、方法、类和对象。不涉及继承、多态、接口、集合、泛型、Stream、Lambda、递归、文件读写、GUI 或交互菜单，也不要求掌握 `Scanner`、异常处理、JUnit、Gradle 或反射。

## 在 IDEA 中开始

1. 安装 JDK 17。用 IDEA 打开本目录 `homework`，按 Gradle 项目加载。
2. 将 Project SDK 和 Gradle JVM 都设为 JDK 17，等待 Gradle 同步结束。
   项目自带 Wrapper，不需要另外安装 Gradle；首次同步需要联网。
3. 打开 `src/main/java/Task01PriceArray.java`，阅读文件开头说明。
4. 主线题：删除练习区域单独成行的 `/*` 和 `*/`，把 `____` 换成代码。
   每题只修改说明中列出的文件与区域，保留题目开头注释、默认变量和测试数据准备代码。
5. 先运行本题的 `main` 观察默认输出，再运行对应测试。
6. 测试通过后继续下一题。附加题不提供填空模板，按说明自行实现。

只需修改 `src/main/java` 中的练习代码，不需要学习或修改测试工具、JUnit、Gradle 配置和 `build.gradle.kts`。

### 临时返回语句

有些方法骨架保留了真实签名，练习代码在块注释中，方法末尾另有一行临时 `return`。完成方法后：

1. 删除练习区域的 `/*`、`*/` 和所有 `____`；
2. 写入正确语句；
3. 删除标注“临时返回语句”的那一行，避免出现不可达语句。

题目和答案都会提醒这一步。`void` 方法没有临时 `return`。

## 题目顺序

主线 18 题以课堂精简版内容为主；第 11 题补充完整版中“this 区分字段与同名参数”的细节，附加题 01 对应完整版静态编号，附加题 02 是综合选做。补充内容不冒充课堂已经讲过的新知识。

六组任务的推进顺序是：

1. **认识数组**：第 01～03 题，创建、读取、修改和按长度创建数组。
2. **循环处理数组**：第 04～06 题，求和、计数和批量修改。
3. **定义与调用方法**：第 07～09 题，参数、返回值、数组参数和方法间调用。
4. **类、对象与构造方法**：第 10～12 题，字段、`new`、`this` 和对象数组。
5. **对象参数与实例方法**：第 13～15 题，把对象传给方法、实例方法和对象间比较。
6. **访问权限与库存规则**：第 16～18 题，`private`、getter、setter 和购买规则。

附加题 01 练习静态编号，附加题 02 综合对象数组、循环和实例方法。

### 附加题

附加题继续平铺在 `src/main/java`，使用 `Extra` 前缀和独立编号，每题都有自己的 `main`。附加题不使用填空形式，题目说明提供思路后由学生自行实现。

- 附加题 01 使用静态字段 `nextId` 保存下一个编号，实例字段 `id` 保存每件商品自己的编号。连续创建三件商品应得到 1、2、3，之后再次读取第一件商品仍得到 1。
- 附加题 02 接收 `Extra02Product[]`，循环调用每个对象的 `stockValue()` 累加。空数组返回 0，零库存商品贡献 0，不修改商品状态。

附加题 01 的编号从 1 开始，测试每次在独立进程中运行，不依赖 JUnit 执行顺序。附加题 02 不需要购物车、菜单、排序或复杂业务功能。

## 多组数据与测试

第 04～06、08 题的测试会用程序参数构造不同的数组数据。测试数据准备代码按“元素个数，随后各元素”的参数顺序构造数组；第 05 题在个数后还有阈值，第 06 题在个数后还有补货量。附加题 02 的参数格式不同：使用若干组“单价 库存”，或用 `empty` 表示空数组。这些解析代码已提供，不需要学习 `String[] args` 或数值解析。

直接运行 `main` 时使用默认数据；自动测试通过程序参数换成其他数据。所有题目都提供了默认样例、不同数据、相关边界和状态检查，防止只打印默认答案。

每道题的测试类名与题目文件对应：

- `Task01PriceArrayTest` … `Task18PurchaseTest`
- `Extra01ProductIdTest`、`Extra02BatchValueTest`

本次共 122 个自动用例。每道题一般有 3～9 个场景；第 09 题分别检查 `square` 和 `calculate`，共 12 个。覆盖范围包括：

- 数组索引 0、中间和最后一个元素；零长度数组；
- 空数组、单个元素、无匹配、全部匹配；
- 阈值恰好相等时不计数；
- 构造两个对象并修改其中一个，另一个保持不变；
- 反射检查第 10、11 题的字段、构造方法和对象独立性；
- 反射检查第 13、14、17、18 题的方法签名和返回类型；
- 反射检查附加题 01 的 `nextId` 是静态字段、`id` 是实例字段；
- 对象数组交换后名称、价格和库存仍属于同一件商品；
- 方法多组返回值和数组未被修改；
- 私有字段通过反射检查访问修饰符，getter 通过真实调用检查；
- setter 接收 0、正数、负数以及连续调用；
- 购买部分数量、恰好买完、库存不足、0、负数、空库存和连续购买；
- 失败后库存保持不变；
- 附加题 01 的静态编号隔离，附加题 02 的空数组、零库存和不修改状态。

数值比较使用 `1e-9` 绝对误差并拒绝 NaN/无穷；字符串、布尔值、整数和数组内容精确检查。输出检查在独立 Java 进程中运行，超过 5 秒或输出超过 64 KiB 会终止并给出提示，因此学生代码中的死循环不会拖死测试进程。

## 运行与检查

在本项目目录运行。Windows PowerShell：

```powershell
# 只检查一道题；换成其他测试类名即可
.\gradlew.bat test --tests Task01PriceArrayTest
# 检查所有题
.\gradlew.bat test
# 只确认主代码和测试代码可以编译，不执行测试
.\gradlew.bat testClasses
```

macOS / Linux：

```sh
./gradlew test --tests Task01PriceArrayTest
./gradlew test
./gradlew testClasses
```

从 ZIP 解压后如果提示没有执行权限，先运行 `chmod +x gradlew`。测试报告在 `build/reports/tests/test/index.html`，只包含最近一次实际执行的测试范围。

也可以直接运行某道题的 `main` 观察默认输出。多数题目支持在运行配置中填写程序参数，参数顺序见各文件开头；数组题按“元素个数，随后各元素”传递，具体见题面。

## 初始状态与完成标准

- **初始项目能编译**：`testClasses` 应成功；未填写的主线填空代码位于块注释中，方法骨架保留可编译的临时返回。第 16 题的访问修饰符和第 17 题的 setter 方法体按题目说明直接补写。
- **未完成题测试失败是正常的**：每道题都至少有一个行为用例无法被占位实现通过。某个失败分支的单独用例可能偶然通过，不代表整道题完成。
- **语法错误会阻止整个项目编译**：测试需要先编译全部主代码。一题漏分号或占位符未删干净，会影响其他题的测试。
- **测试通过表示行为符合要求**：实际输出、返回值、状态变化与预期一致。
- **测试不是全部要求**：除了少量必要的字段/构造方法结构检查，测试不分析源代码，不能自动证明“使用了 for”“calculate 调用了 square”“构造方法写了 this”“交换的是对象引用”。这些要求需要对照题目人工核对。

### 需要人工核对的要求

| 题目 | 自动测试之外还要检查 |
| --- | --- |
| 第 04～06 题 | 使用普通 `for` 循环和数组 `length`；第 06 题逐个修改元素，不能只算总和 |
| 第 08 题 | 方法内部使用循环求和，且没有修改传入数组 |
| 第 09 题 | `calculate` 确实调用了 `square`，没有重复写 `x * x` |
| 第 10 题 | 字段类型分别为 `String`、`double`、`int`；两个对象各自创建 |
| 第 11 题 | 构造方法与类同名、没有返回类型；参数与字段同名；用 `this` 初始化全部字段 |
| 第 12 题 | 用临时变量交换数组元素，不是逐个复制字段 |
| 第 13 题 | 静态方法通过参数对象读取数据，没有用静态字段保存某件商品 |
| 第 14 题 | 实例方法不写 `static`，不额外接收当前商品参数 |
| 第 15 题 | 使用 `this.price` 与 `other.price`，相等时返回 `false` |
| 第 16 题 | `stock` 是 `private`，`main` 不直接访问字段 |
| 第 17 题 | 方法返回类型是 `void`；负数输入不改变库存；方法内不打印 |
| 第 18 题 | 失败分支不扣库存；调用方同时检查返回值和库存；方法内不打印 |
| 附加题 01 | `nextId` 是静态字段，`id` 是实例字段；编号从 1 开始 |
| 附加题 02 | 循环中调用每个对象的 `stockValue()`，不重新写公式 |

## 项目与网络配置

采用 Gradle 9.6.0 + JUnit Jupiter 6.0.0，沿用第二次作业和课堂 SampleGUI 的版本及换源方式：

- Wrapper 从腾讯镜像下载 Gradle，保留原有 SHA-256 校验值；
- Java 依赖优先使用阿里云公共 Maven 仓库，Maven Central 作为后备；
- 只使用 Gradle 内置 Java 插件，没有第三方构建插件；
- 源文件使用 UTF-8，编译目标为 Java 17；提供 Windows 与 Linux/macOS 的 Wrapper 和运行命令，本次实际验证在 Linux 上完成；
- `.gitignore` 排除构建结果、IDE 个人配置和缓存。

网络不可用时 Gradle 可能无法首次下载依赖，这不属于学生代码错误。完整缓存后可以加 `--offline` 检查；缓存不全时仍需要联网。
